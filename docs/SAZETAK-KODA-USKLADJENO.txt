4) FIRESTORE / EDGE / KEŠ (DETALJNO)
================================================================================

4.1 Šta Firebase Usage graf NE znači intuitivno
--------------------------------------------------------------------------------
- Broji SVE naplative dokument-readove u projektu u intervalu: klijentski SDK,
  Worker (Firestore REST runQuery/get), druge usluge, testovi, drugi tabovi.
- „Drugi put samo keš“ na tvom uređaju ne garantuje nizak broj u konzoli: drugi
  korisnici, istek edge keša, više upita sa velikim N (N dokumenata = N readova).
- Jedan uspešan HTTP poziv ka Workeru koji vrati N redova iz Firestore-a može
  predstavljati N readova — „jedan poziv“ nije „jedan read“.

4.2 Edge — redosled keša (workers/index.ts, servePublicCached)
--------------------------------------------------------------------------------
- (a) in-memory isolateCache po normalizovanom URL-u
- (b) KV env.FIRESTORE_CACHE ako je povezan
- (c) Cloudflare caches.default
- (d) handler → Firestore REST
- Tipične konstante: EDGE_CACHE_TTL_SECONDS=3600, KV_CACHE_TTL_SECONDS=6h,
  mem TTL nakon miss podrazumevano ~10 min (600000 ms) — proveri u fajlu ako
  se menja.

4.3 Klijentski keš
--------------------------------------------------------------------------------
- resilience.ts: localStorage + expiresAt
- cachePolicy.ts: CACHE_TTL, REFRESH_INTERVAL; sa Quota Saver-om duži interval
  (npr. USER_LIGHT_1H 4h umesto 1h u QS režimu).
- refreshGate: isti ključ za mount i focus za isti „paket“ osvežavanja.

4.4 Primer puta: etiketa + destilerija
--------------------------------------------------------------------------------
- Label.tsx: fetchPublicLabelView → GET /api/public/label-view/:id
  (Worker: product + distillery + do ~8 ratings po miss-u keša); gost saved:
  getDoc guest_saved_items kada nema lokalnog keša.
- Distillery.tsx: fetchPublicDistilleryById; fetchPublicProductsByDistilleryId
  (paginacija; manji page u quota saver); fetchPublicClubMembershipsByVisitorId
  (limit 30); fetchPublicClubMembershipCount; lokalni writeCache + refresh gate.

4.5 Zašto broj u konzoli i dalje može biti veliki
--------------------------------------------------------------------------------
- loadMore: svaka stranica = novi URL (?after=) = novi upit.
- Članstva: do 30 dokumenata po promazu keša na tom endpointu.
- Više Worker izolata: mem-hit nije deljen; KV/CF smanjuju miss.
- Nepodudaranje deploy-a: stari bundle ili pogrešan edge base → više
  fallbacka (ređe uz FORCE_EDGE_ONLY).
